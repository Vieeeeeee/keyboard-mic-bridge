## 已完成

- Swift 单文件菜单栏应用；麦克风、输入监控授权后转发内置麦克风到虚拟设备。
- Fn 长按、短按持续、再次 Fn／Esc 停止，SayAll 日志推断遥控器优先。
- 音频启停移到后台串行队列；会话代次防止旧启动结果重开收音。
- 待机日志改文件事件通知；仅收音时每秒一次健康检查与界面刷新。
- 播放排队限约 250ms；无输入超过 3 秒、输出停止、日志更换等情况停用。
- 睡眠／会话失活停用与单段 30 分钟限制已编码，实际故障矩阵未完整验证。
- 关闭窗口后留菜单栏；提供停止、退出与虚拟回环自检。

## 实际验收时间线

1. 遥控器出字，键盘 Fn 打开豆包但不出字；固定虚拟输入时缺少电脑音频。
2. 经多轮修正，用户确认 Fn 长按出字；点按起初没有波形。
3. 后来用户确认长按与点按均成功。
4. 优化版用户确认长按、点按与超过一分钟持续出字：“都正常，超过一分钟也出字”。这证明电脑链路曾成功超过一分钟，与遥控器硬件上限是两件事。
5. 随后键盘又失效，遥控器仍能用。只停用再启用本工具，未重启豆包或 SayAll，用户确认恢复。
6. 查出并修正一个确定缺陷：遥控器结束后的 400ms 避让期间，Fn 按下被丢弃。旧实现回归检查失败，修正后通过。
7. **最终用户再次报告“键盘仍会失效”，因此该修正没有完全解决问题。** 本轮按用户要求整理交接，不继续更改收音逻辑。

曾有界面残留“遥控器正在收音”提示，但日志已有 STOP；这不足以证明内部 remote 状态一定卡住。恢复操作也不能单独证明是哪一层出错。

## 2026-11-11 晚：用户确认可用

长按、点按、点按后按回车／点鼠标再点按、遥控器与键盘交替，用户实测均出字（“都测过了，现在都行了”）。长期稳定性仍待观察。

遥控器相关结论（未改动，属于 SayAll／遥控器固件范围）：
- 点按开关式录音：SayAll（无线麦）自带“持续录音实验功能”（按键映射里，`experimentalContinuousRecordingEnabled`，当前关闭），本工具无法替代。
- 单次 1 分钟上限：SayAll 自己的说明写明“单次最长 1 分钟”，是遥控器链路限制，本工具无法延长。

### 遥控器持续录音实测（2026-11-11 18:07）

用 `--rc003-voice-extension-test` 启动 SayAll 后，它自动跑了延长测试：`RC003 EXTENSION test_started max_duration_s=120` → 8 秒后 `MIC_EXTEND failed` → `stopping reason=extend_rejected`。即遥控器固件拒绝延长麦克风会话，点按式持续录音与突破 60 秒在这台 RC003 上都不可行。`experimentalContinuousRecordingEnabled` 每次启动都被 SayAll 重置为关闭。已用普通方式重启 SayAll 恢复原状（`rc003_test=false`）；修改前的 SayAll 设置备份在 `private/`（不进 Git）。
