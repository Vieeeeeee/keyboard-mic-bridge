# 已知问题

## 2026-11-11 自愈改版（待用户实测）

找到的确定问题与改法：

| 问题 | 证据 | 改法 |
|---|---|---|
| 任何小故障都调用 `fail()` 整体停用，之后 Fn 只弹豆包、没音形，直到手动重新启用 | 源码；与“停用再启用能恢复”吻合 | 改为 `interrupt()`：只结束本次收音，保持启用 |
| 每次按 Fn 都把引擎重新绑到 MiRemoteV 2ch，和 SayAll 互相触发设备重配置、停掉对方引擎 | SayAll 日志约 570 次 `engine_configuration_change` 恢复 | 输出引擎尽量常驻；待命时被重置就放手、下次按 Fn 重建；收音中被重置则原地重启（10 秒内最多 3 次，且须仍绑在 MiRemoteV） |
| 事件监听被系统暂停后整体停用 | 源码 | 立即重新开启监听并按真实 Fn 状态校正 |
| 日志轮换后停用 | 源码 | 跟随新日志文件 |
| 遥控器 STOP 丢失会永久屏蔽 Fn | 推断 | 超过 75 秒无 STOP 视为结束（已加自检） |
| 点按模式与豆包不同步：按回车等键豆包已结束，下一次点按被当成“停止” | 用户实测复现 | 任意实体按键或鼠标点击都结束点按模式（原浮层判断在本机识别不到浮层，已删除） |

**2026-11-11 17:18 实测出字（主因已确认）**：MiRemoteV 2ch 每次被本工具接上都会触发一次引擎配置变更；原地重启时播放器里残留的旧缓冲会把后续声音全部堵死（队列满、无回放回调、虚拟通道音量为 0）。修法：重启前 `p.stop()` 清空。用独立进程读虚拟通道音量验证：修前 0，修后有声；用户确认长按、点按出字。遥控器之后紧接键盘这一组当次没测到。

**按键改从键盘硬件读取（2026-11-11）**：实测发现系统按键信号不可靠——Fn 点按松开后会多出一个 keycode 179 的 keyDown；豆包浮层开着时 Fn 信号偶尔整段收不到（被截走）。现在 Fn 与“其他键”用 IOHIDManager 直接读内置键盘（Fn＝页 0xFF 用途 0x03，普通键＝页 0x07），只有鼠标点击仍走事件监听。SayAll 注入的 Fn 不会出现在硬件层。外接非 Apple 键盘的 Fn 读不到。

**授权坑**：在「输入监控」里改权限后，正在运行的进程按键监听会静默失效（tap 显示启用但收不到 Fn），必须重开 app。每次重新编译（临时签名）都要重新授权。


## P0：电脑 Fn 间歇失效（见上方改版，待实测）

现象：使用一段时间或遥控器／电脑切换后，键盘 Fn 无法出字，遥控器仍可用；曾仅停用并重新启用本工具恢复。没有稳定的最小复现步骤。

已修正的确定问题：`Intent.key` 曾丢弃遥控器 STOP 后 400ms 内的按下。现在保留意图、延后启动，同时覆盖短按与停止键释放；当前源码包含这次修正，用户仍报告失败。

以下均是**待验证假设**，不是确定根因：

| 可能位置 | 要抓的最小证据 |
|---|---|
| Fn 监听中断／权限／多个副本 | 当前 PID、实际执行路径、tap 是否启用、是否收到 down/up |
| 日志推断 remote 错误或过期 | 当前 remote、最近 START/STOP 时间、文件 inode/offset，避免保留全量日志 |
| Fn 手势与豆包手势不同步 | downAt、latched、blockedUntil、豆包是否仍在识别；不记录语音内容 |
| 后台音频生命周期竞争 | generation、preparing、启动／取消／停止顺序；取消后是否有旧回调 |
| 采集或虚拟输出停滞 | 输入包数、最近包时间、排队帧数、实际绑定设备、引擎状态 |
| 虚拟设备或豆包自身会话 | 桥接是否仍输出、豆包是否收到波形，分别验证 |

排查时应在重置前截取状态。不要因“重启能恢复”直接归因。当前缺少统一状态时间线，建议先补最小诊断，再修复证据支持的缺陷。

## P1：本工具和豆包停止状态不同步（2026-11-11 已改）

豆包遇到任意按键或鼠标点击都会结束（回车上屏，其他取消；滚轮不算）。本工具点按模式现在对任意实体按键／点击同步结束。已实测确认：豆包上屏时不会模拟按键（事件来源进程号都是 0）。剩余缺口：豆包超时自己结束时本工具不知道。

建议优先研究可靠的识别会话结束信号；任何自动恢复、录音状态变化都需明确呈现。健康检查只知道音频有没有数据，不知道豆包是否接受文字。

## P1：遥控器状态依赖日志

`~/Library/Logs/RemoteMic/runtime.log` 的 START／STOP 字符串是版本耦合的间接信号，不区分 Fn 来源，也不是稳定 API。日志轮换会跟随新文件，读不到时暂停遥控器避让并每 5 秒重试；每次打开只重读末尾 128KiB，不能保证还原真实硬件状态。

## P2：设备命名与权限身份

- 输入名称必须同时含 `MacBook` 与 `麦克风`，输出名精确匹配 `MiRemoteV 2ch`。不具备通用设备选择。
- 临时签名，未公证。新二进制或路径变化可能需要刷新权限。
- 多个相同 bundle ID 的 `.app` 曾导致系统“退出并重新打开”选择错误副本；仅改 `.app` 扩展名不足以避免注册，历史构建还需将 Info.plist 改作模板。本项目只在临时目录构造应用，输出 ZIP，不留展开副本。
- 云盘目录附加 Finder 元数据曾导致签名失败，构建改在 `/private/tmp`。不要通过关闭安全限制解决。

## 遥控器本身的两项限制

RC003-MS 当前链路需要长按；约 60 秒音频会结束，历史日志有约 60056ms／60066ms 的会话。当前没有已验证的 macOS 解法。改用云端识别或本地识别都不能补回硬件没发来的音频。其他项目的 keepalive／重连方案应先验证型号、系统和连续音频，不能只看宣传。
