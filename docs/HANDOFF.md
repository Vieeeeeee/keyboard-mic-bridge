# 给下一位 Agent

## 从这里开始

先理解“桥接音频”和“识别会话”是两套状态：本工具监听 Fn，却不会直接通知豆包开始／结束；豆包独立监听同一个快捷键。本工具用 SayAll 日志判断遥控器，监听到的 Fn 也没有设备来源身份。请不要只调一个延时便宣告完成。

本次只归档当前行为，未再次修复。应用标题及授权提示仍保留历史测试版文字；项目最新状态以 STATUS.md 为准。历史对话无需上传即可接手。

## 源码入口（单文件，无第三方依赖）

| 符号 | 职责与关键值 |
|---|---|
| `Capture` | AVCaptureSession 采集，要求 16kHz／单声道／Float32 PCM；采集队列回调转 AVAudioPCMBuffer |
| `Intent` / `selfCheck()` | 纯状态：200ms 长按意图，300ms 短按界限，400ms 遥控器避让，Esc 取消持续模式 |
| `Bridge.activate()` | CGEvent listenOnly tap；回调异步到主线程；文件变更监听 |
| `openLog()` / `pollLog()` / `parse()` | 末尾 128KiB 初始化、inode／offset 增量读取、START／STOP／断线／APP START 推断 remote |
| `updateAudio()` | 根据意图启停；录音期间每秒健康检查；3 秒无输入、输出停、30 分钟限制 |
| `startAudio()` | 后台串行启停，绑定虚拟输出，主线程提交启动结果；generation 拦截旧会话结果 |
| `stopAudio()` / `disableBridge()` | 递增 generation、清空引用与定时器、后台停止音频；停用同时移除事件与日志监听 |
| `testRoute()` | 440Hz 测试音送虚拟输出并回读 3 秒；会停用桥接，不验证实际出字 |

主线程处理控制状态与每包播放排队。上限 4000 帧基于 16kHz 假设，相当于约 250ms。`lastAudioAt` 来自输入包到达，不代表豆包收到声音。原型普通转发已去掉峰值扫描，所以不能把常态 peak=0 直接判断成没收音。

## 曾尝试与修正

- AVAudioEngine 直接采集曾遇到 -10868，改为 AVCaptureSession 输入。
- 事件 tap 中直接启动音频曾导致阻塞，移至后台处理。
- 普通 keyDown 停止持续模式会被输入法注入文字干扰；PID=0 判断不足以可靠区分，最后只保留 Esc。这造成当前与豆包停止状态不一致的风险。
- 优化版撤除高频日志轮询、限制排队和界面刷新；连续录音性能尚未量化。
- 遥控器停止避让期间忽略 Fn 按下的缺陷已加回归并修正，**但最终用户仍报告失效**。

## 先自检，再做实机分层测试

`bash scripts/test.sh` 只验证 Intent 的按住／点按／停止／普通文字不停止／遥控器优先／不自动恢复／避让期输入。未覆盖日志解析、并发、音频生命周期、权限、硬件和豆包。

实机建议按顺序确认：唯一运行实例与权限 → Fn 事件 → Intent → Capture 输入包 → 虚拟输出回环 → 豆包波形 → 文字上屏。失败时先记录脱敏状态，再停用重启。不能将签名通过或虚拟回环通过当作最终用户验收。

后续测试至少包括：键盘独立长按与点按各多轮、点按超过 75 秒、遥控器与键盘快速交替、普通键结束豆包时是否仍采集、Esc 停止、日志轮换、SayAll 重启、锁屏睡眠、音频设备断开。涉及说话与出字请由用户现场完成，不自行采集私人录音。

## 构建与路径经验

构建脚本使用临时目录与临时签名，只保留 ZIP，避免 Finder 元数据干扰签名及多应用副本注册。模板保持测试 bundle ID `design.abdc.KeyboardMicBridge.Test`，不代表权限一定会继承。只运行一个固定路径的应用。没有自动安装、权限重置或开机启动脚本。

历史二进制与优化前源码不是已验证的一一对应关系，比较时以 SHA256SUMS 识别文件，不能据同名宣称可复现。当前源码可由附带脚本重建；Swift／SDK 版本变化也会改变二进制。
